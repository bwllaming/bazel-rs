# `starlark_doc_extract`

The native `starlark_doc_extract` rule (Bazel 9.3.1
`rules/starlarkdocextract/StarlarkDocExtract.java` with the extractor in
`starlarkdocextract/*.java`) documents one loaded `.bzl` module as a
`stardoc_output.ModuleInfo` (`src/main/protobuf/stardoc_output.proto`). This
is what Stardoc 0.7+ runs before its renderer. Code: `src/starlark_doc_extract.rs`
(extractor and proto encoders) and `src/engine/starlark_doc_extract.rs`
(analysis). Genuine-captured tests: `tests/starlark_doc_extract.rs` over
`tests/fixtures/starlark_doc_extract` (`reference_receipt.json`).

## Outputs

* `NAME.binaryproto` — `ModuleInfo.toByteArray()` (BinaryFileWriteAction):
  the target's files to build and runfiles.
* `NAME.textproto` — `TextFormat.printer().print(ModuleInfo)` (FileWriteAction):
  an implicit output, built when requested (`//pkg:NAME.textproto`).

Both are native file writes (mnemonic `FileWrite`). Both encoders emit fields
in field-number order, omit proto3 scalars at their defaults and keep set
message fields even when empty (`origin_key {}`), as protobuf-java does. The
text form escapes like `TextFormat.escapeBytes` over UTF-8 (`\'`, `\"`, octal
`\303\251` for non-ASCII bytes).

## Analysis

* `src` must resolve to exactly one source file (a filegroup or alias to one
  works): `'//pkg:fg' must produce a single file` and
  `pkg/gen.bzl (generated by rule //pkg:gen) is not a source file and cannot be loaded in Starlark`
  are genuine's `in src attribute of starlark_doc_extract rule //pkg:x: …` errors.
* The module is loaded through the shared BUILD-phase `.bzl` cache (the
  `keyForBuild` load), so its `print()`s and load errors behave like any
  BUILD-phase load (`in src attribute …: <load error>`; the load error text is
  native, not genuine's BzlLoadFailedException text).
* `deps`: the source files to build of every dep (any rule; `bzl_library`'s
  `StarlarkLibraryInfo` is not read, only its files, like genuine) must cover
  the module's transitive loads: a preorder over the load graph reports the
  topmost unknown modules, `missing bzl_library targets for Starlark
  module(s) //lib:dep.bzl`, with genuine's generated-file note.
* `render_main_repo_name`: labels of the main repository render as
  `@<root module name>//…` (`_main` when the root module has no name).
* `symbol_names`: a qualified name is documented when it or an ancestor
  struct name is listed; provider names used in rule/attribute provider lists
  ignore the filter.
* `allow_unused_doc_comments`: as genuine.

## Extraction (ModuleInfoExtractor)

The module's globals in first-binding order (load bindings excluded), public
names only (first character alphabetic), recursing into `struct`s and provider
instances (fields by name). Unexported rules, providers, aspects, macros and
repository rules are skipped. Per kind:

* **rules** (`RuleInfo`): the implicit `name`, then the Starlark-declared
  attributes in declaration order (private ones and a build setting's
  built-in `build_setting_default`/`help` excluded); `test`, `executable`
  (also for tests), `advertised_providers` from `provides`, origin key
  (exported name, the exporting `.bzl`).
* **attributes** (`AttributeInfo`): `AttributeType`, trimmed `doc`,
  `mandatory`, provider groups (documented name: the first qualified name of
  the provider in this module, else its exported name; `<native>` for
  built-in providers), `default_value` as genuine's
  `reprWithoutLabelConstructor` (labels as shorthand display strings),
  `values`, `nonconfigurable` (outputs, `configurable = False`),
  `natively_defined`.
* **providers**: fields in declaration order with docs, `init` when it is a
  Starlark function (documented under the provider's qualified name).
* **functions** (`StarlarkFunctionInfo`): parameters in Bazel's order
  (ordinary, keyword-only, `*args`, `**kwargs`) with defaults as
  `LabelRenderer.repr` (`Label("//pkg:x")`), docstrings parsed exactly like
  `DocstringUtils` (summary, `Args:`/`Arguments:`, `Returns:`,
  `Deprecated:`, parameter attributes in parentheses, continuation lines);
  any docstring parse error fails the rule with genuine's message. The
  origin key names the first global of the defining module bound to the
  function (so lambdas and private implementations resolve as in genuine).
* **aspects** (`attr_aspects` public names, attributes), **symbolic macros**
  (implicit `name`/`visibility`, attributes, `finalizer`), **repository
  rules** (`name`, attributes, `environ` in declaration order), **module
  extensions** (tag classes in order, with their attributes; origin key
  without a name, as genuine).
* **other symbols**: a global with a `#:` doc comment block (or a trailing
  `#:` comment) documents as `StarlarkOtherSymbolInfo` with its `type()`;
  a doc comment attached to a function/rule/… or to nothing fails with
  genuine's messages, unless `allow_unused_doc_comments`.

Docstrings are trimmed by `Starlark.trimDocString` over the Latin-1 chars of
the UTF-8 source, as Bazel holds `.bzl` strings: tab expansion counts bytes,
so `ü\t` expands like genuine.

## Load-time changes for documentation

The values the extractor reads now retain their `doc` (rules, attributes,
providers, aspects, macros, repository rules, tag classes, module
extensions), provider field order, repository-rule `environ` order, tag
class and tag attribute order, and a module extension's defining file. None
of this enters serialized schemas or keys (the attribute fields are
`#[serde(skip)]`). Every `attr.*` function takes Bazel's `configurable`
(bool or unbound): `rule()` rejects a set value with genuine's text,
symbolic macros keep `configurable = False` as non-configurable, repository
rules and tag classes accept it like the reference. `macro()` with user
attributes or `finalizer = True` now loads (documented); invoking such a
macro still fails explicitly (`macro user attributes are unsupported`,
`macro finalizer=True is unsupported`, docs/SYMBOLIC_MACROS.md).
`inherit_attrs` remains unsupported at definition.

The vendored interpreter gains one read-only accessor,
`starlark::eval::def_documentation` (a `def`/`lambda`'s raw docstring,
location, parameter names and its module's globals; docs/STARLARK_VENDOR.md).

## Validation

Byte-identical binary and text protos against genuine 9.3.1 for every kind,
both label renderings, `symbol_names`, filegroup `src`, external-repository
modules and labels, and `bazel_skylib` 1.8.2's `lib` and `rules` modules
re-exported from the main repository (`docs/` in the fixture); genuine's
error messages for missing deps, generated sources, multi-file sources, doc
comment errors and malformed docstrings. Stardoc 0.8.0's `stardoc()` macro:
its `NAME.extract` output matches genuine byte for byte; the renderer itself
is not built natively (its protobuf dependency's zlib genrule uses
`cmd_bash`, an existing native genrule gap).

## Divergences

* A function's location in a docstring error names the file path for the
  extracted module only; functions re-exported from other modules show the
  label.
* The main repository mapping is ordered by apparent name natively, so a
  repository visible under two apparent names renders with the first by
  name (genuine: insertion order; docs/REPR.md).
* `inherit_attrs` macros and `@_builtins` modules are not documented.
