# Historical repository publication selection (staged implementation)

One repository specification may have multiple retained publications. Watched
runtime inputs participate in publication identity separately from the recipe's
specification key, including when generated bytes do not change. A retained
configured graph therefore cannot ignore a changed specification-pointer READ.

## Implemented

Live direct/ordinary repository selection records an **advisory receipt** with
canonical repository, versioned recipe origin, specification key, publication
identity, shared/workspace scope, and a semantic manifest digest. The digest
covers format/profile, identity/specification, recorded runtime probes, slot
classification and inventory. Refreshable stat hints and informational GC
references are excluded. Workspace paths retain raw bytes.

Receipts travel through detached observation captures, INPUTS format 5, history
versioning, incremental recording merges, refresh and verify. Selection-owned
pointer reads/absence checks are distinct operations; ordinary READs of the same
path remain independent guards. Source/environment and REPO/INTEGRITY obligations
remain in force. Receipts neither grant CARRIED authority nor classify repository
changes as package-only changes. Build/incremental snapshots currently validate
the typed pointer operations strictly; historical adoption is cquery-only.

`RepositorySet::prove_publications` creates a fresh, private preparation set from
current invocation options/environment/host inputs. It reopens the current
lockfile choice and recomputes direct or ordinary spec keys using the normal
preparation functions. A valid ordinary extension lock entry must pass the normal
source, usage, mapping, environment, input and facts checks. Invalid entries miss
before extension evaluation. Preparation heaps are shared per group and released
before returning compact, non-deserializable point-in-time proofs.

The supported closure includes current module dependencies and transitive loads:

- Local override and registry-local source roots selected by current metadata.
- Registry metadata read from local registries or CAS named by **current reopened
  lockfile checksums**, never an old URL memo. Missing checksums/data, mutable
  remote metadata and refresh mode miss without transport or prefetch.
- Already published registry archives under the existing source/overlay/patch
  key, current compiled built-ins (with normal filesystem precedence), and fully
  pinned Git sources under their normal remote/commit/strip/patch key. Pure
  verification returns before staging, fetching, Git invocation or repair.
- Non-local direct rules and ordinary extensions with current valid lock entries.
  Generated definition/runtime roots require their own receipt and recursive
  current-spec/runtime/integrity proof **before loading**. Existing demand-slot
  cycle/depth checks apply. All producer receipts must be in the candidate batch.
- Friendly workspace, candidate `stage:`, and `@@repo//` runtime probes through
  current proved roots, without symlink hops. Declared/watched environment values
  are checked normally.

Seeded hidden lock entries, arbitrary absolute runtime paths, local rules,
diagnostic-producing preparation and mutable roots are conservative misses.
Retained bytes, old pinned tables and old prepared memos never certify current
producers. The private proof records current resolution, source and runtime reads;
producer identity locks join the adoption lock set, and a changed producer closure
after lock acquisition misses before mutation.

The store's read-only probe uses the same validation kernel as normal reuse.
It checks current shared then workspace pointer winners first. A different valid
winner rejects the candidate; a historical ID is considered only when current
pointers are not reusable. Missing selections, malformed pointers, unknown/legacy
probes, force-fetch, missing/tampered data and mutable slots miss. It never scans
publication history, refreshes manifests, changes pointers/slots, or uses CARRIED.

## Guarded cquery adoption

For the supported closure, cquery can accept the graph's historical publication.
Only explicitly selection-owned operations, backed by the matching receipt and
REPO record, are discharged by proof. A generic READ of precisely the same path
still has to match. Re-probing after execution supersedes only that selection's
own operations, preserving unrelated consumers.

Candidate proof uses a thread-private recording of current preparation/runtime
inputs. Ordinary observations, EVENTS, PLAN and all graph indices must validate
before adoption. Default cquery retains the early strict lookup, ordinary local
replay and saved diagnostics. The native `BAZEL_RS_CQUERY_CURRENT_LOADING=1/on`
opt-in uses sealed current-loading results instead, in a separate cquery history
namespace. See [CQUERY_CURRENT_LOADING.md](CQUERY_CURRENT_LOADING.md) for its exact
local coverage and silent-prefix/empty-EVENTS boundary. It is default off.

Adoption takes the existing per-canonical slot writer locks and publication
identity locks without waiting. Busy acquisition releases all held guards and
misses before mutation. Normal publishers, ordinary reuse binders, mutable-slot
conversion and speculative pointer withdrawal participate in the same slot
protocol. Binders do not wait while a dependent repository might hold another
lock. Identity locks exclude refresh/republish and normal GC. No new persistent
lock namespace or history index is added.

Under these locks acceptance recomputes current intent and pointer preference,
checks the manifest/runtime/inventory again, and revalidates ordinary and both
private proof recordings. Only then does it install the exact scoped pointer and
immutable native external slot. Marked or real mutable roots are never replaced.
The link and selected pointer are checked before reporting a hit. Any error once
installation starts is terminal for the command, never another candidate's miss.
Multi-file crash atomicity is not claimed: a pointer/view mismatch on restart
refuses the strict fast path and requires full revalidation/repair.

The pure API's A/B/A/B tests still prove no public mutation. Separate CLI tests
now require four historical hits, exactly two generator executions, and matching
pointer, graph and actual external bytes for constant and changing output, direct
and valid-lock extension cases. Late invalid graph indices, changed input/winner,
mutable markers, busy publishers, missing data and partial-commit recovery are
covered. Additional CLI tests cover registry local/archive sources, module deps,
recursive generated definitions, and built-in filesystem precedence under module
overrides. Counters cover generators and extension callbacks; registry transport
and Git-fetch counters stay zero during pure proof.

Historical nonlocal switching with local replay remains unsupported by the default
path; its already-working strict-pointer local replay is preserved. The explicit
current-loading experiment supports only locals already required and completed
by the current prefix. The saved V3 graphs each have45 local records whose full
neededness is not established by pattern loading, and nonempty EVENTS. The opt-in
therefore does **not** unblock that application/TD probe, and remains default off.
No historical record can add a demand to fill missing current coverage.
